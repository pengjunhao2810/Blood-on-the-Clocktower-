# 系统架构设计文档

## 一、总体架构

```
┌──────────────────────────────────────────────┐
│                 浏览器（Vue3 SPA）             │
│  index.html + app.js（WS 客户端 + 状态管理）   │
└───────────────┬──────────────────────────────┘
                │ WebSocket（全双工指令/广播）
                │ HTTP（认证/建房/战绩/回放/静态资源）
┌───────────────▼──────────────────────────────┐
│            Go 游戏主服务（8741）               │
│  Gin HTTP 层 ── handler（认证、路由）          │
│  WS Hub ───── 房间广播 / 用户定向推送          │
│  房间 Actor（每房间一个 goroutine 事件循环）    │
│    ├── 引擎 engine（纯逻辑状态机）             │
│    ├── 相位推进定时器（夜晚2s/辩论20s/投票20s） │
│    ├── 私聊会话 / 挂起选择 / 持久化落盘        │
│    └── 空置清理（离线3分钟复位）               │
│  GORM + SQLite（单连接，busy_timeout）        │
└───────────────┬──────────────────────────────┘
                │ HTTP（/api/speak /api/decide）
┌───────────────▼──────────────────────────────┐
│          Python AI 服务（8742）               │
│  DeepSeek 大模型（无 Key 时模板降级）          │
└──────────────────────────────────────────────┘
```

## 二、核心设计决策

| 决策 | 理由 |
|---|---|
| 房间 Actor 模型 | 每房间独立 goroutine + 事件队列，天然避免锁竞争；定时器统一驱动相位流转 |
| 引擎与 IO 分离 | engine 包纯逻辑可单测；广播/持久化由 room 层负责 |
| WS 全双工指令 | 游戏实时性要求高，HTTP 轮询延迟不可接受 |
| SQLite 单连接 | 单机毕设场景，避免并发写锁竞争；连接池=1 + busy_timeout 兜底 |
| AI 服务独立进程 | 大模型调用慢且不稳定，进程隔离防止拖垮主服务；无 Key 模板降级 |
| 对局持久化 | 5 秒落盘 + 重启恢复（角色/相位/挂起），空置 3 分钟自动清理 |
| 聊天卡片式交互 | 定向卡片（夜间技能，仅本人可见）+ 广播卡片/横幅（投票、提名），无模态弹窗 |

## 三、游戏流程状态机

```
waiting → night（夜晚逐步执行，2秒/步，真人挂起45秒）
        → day（黎明公布死亡）
        → private_chat（点击玩家条目邀请私聊，一对一面板切换）
        → public_chat（公聊，AI 自动发言）
        → nomination（点击条目提名 → 辩论20s → 投票20s → 30s冷却 → 汇总处决）
        → night（循环）／游戏结束
```

### 夜晚顺序（官方）
- 首夜：minion_info → demon_info → poisoner → spy → washerwoman → librarian → investigator → chef → empath → fortune_teller → butler
- 其他夜：poisoner → monk → spy → scarlet_woman → imp → ravenkeeper → undertaker → empath → fortune_teller → butler

### 提名处决规则
1. 一轮提名阶段可多组提名、多场投票
2. 每次投票结束开启 30 秒冷却窗口
3. 冷却到期汇总全部被提名者票数：**唯一最高票且 > 存活半数 → 处决并入夜**；并列最高或未过半 → 无人处决

### 中毒机制
- 状态仅服务端保存（json:"-" 不序列化），玩家无感知
- 信息类（占卜师/共情者/送葬者/守鸦人/厨师等）：返回虚假结果
- 效果类（僧侣/投毒者）：流程照常，效果不写入
- 恶魔免疫投毒；死亡 > 中毒（死亡角色直接禁用技能）

## 四、数据库（SQLite）

| 表 | 说明 |
|---|---|
| users | 用户（bcrypt 密码） |
| rooms | 房间（status/game_data 对局快照） |
| room_seats | 座位（含 AI 座位） |
| friends | 好友关系 |
| game_logs | 对局归档（参与者 uid、角色/消息/行动 JSON，战绩+回放） |

## 五、关键接口

| 接口 | 说明 |
|---|---|
| POST /api/auth/register、/login | 认证 |
| GET /api/me | 会话检查 |
| POST /api/room/create | 建房 |
| GET /api/stats、/api/games、/api/game/:id/replay | 战绩与回放 |
| WS 事件（节选） | game.night_tip（夜间定向卡片）、game.vote_start/result、game.private_invite/message、game.nominate 等 |
